What powers this

Tech Stack

Web layer

Django

The application is built with Django, a Python web framework that keeps the backend clean and Pythonic. It handles routing, templating, and serves as the glue between the frontend and the retrieval pipeline.

Django was chosen for its simplicity and because the rest of the stack — Boto3, Requests — is all Python. No context switching, no separate services for the web layer.

Django 5 Python 3.12 Jinja2 Templates Boto3
Knowledge base & retrieval

AWS Bedrock

AWS Bedrock Knowledge Bases handles the heavy lifting of the RAG pipeline — document ingestion, chunking, embedding, and vector storage. When a query comes in, Bedrock's retrieval API returns the most semantically relevant chunks ranked by similarity score.

The app uses the Retrieve-only mode, intentionally skipping Bedrock's built-in generation. This keeps generation local and free, while still benefiting from Bedrock's managed vector search infrastructure.

Bedrock Knowledge Bases Retrieve API Vector Search S3 (document store)
Local inference

Ollama

Ollama runs a large language model locally on the same machine as the Django app. Retrieved chunks from Bedrock are assembled into a prompt and sent to Ollama's REST API, which returns a generated answer grounded in that context.

Running inference locally means zero generation cost regardless of query volume. The tradeoff is hardware — a decent GPU or Apple Silicon chip is recommended for acceptable response times.

Frontend

Vanilla HTML & CSS

No JavaScript framework. The UI is built with plain HTML, CSS, and Django templates. This keeps the frontend lightweight, fast to load, and easy to maintain without a separate build step or node_modules folder.

Typography is set in DM Serif Display and DM Sans from Google Fonts. The warm off-white palette and minimal layout are intentional — the focus stays on the content, not the chrome.
